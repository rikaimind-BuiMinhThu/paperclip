Prerequisites

API endpoint

    /api/client/v1

Authorization: Bearer pcp_cust_...

A call is not valid until every item below is true.

  1. A board operator, in company settings under API Apps, creates an API app and sets its default agent.
  2. The operator creates a customer on that app. The customer is active and has a plan.
  3. The operator issues a pcp_cust_ key and gives it to the client. The key is shown once.
  4. The API app and the customer are both active.
  5. An agent is bound: the customer's default agent, otherwise the app's default agent. If neither is set, every chat call returns 409 AGENT_NOT_BOUND.

Every call sends Authorization: Bearer pcp_cust_.... The key already identifies the company, the API app, and the customer. The client does not send companyId and cannot pick an agent.

A client app holds a multi-turn conversation with the agent bound to its API app. External chat is transport. Paperclip remains the authority for the agent, the task, the run, budgets, and approvals. The client sees published replies. It does not see run logs, tool traces, chain-of-thought, secrets, or board-only comments.

These routes are not implemented yet.

Token and spend for the same key is GET /api/api-app-customers/me/usage. Pages processed and credits remaining are GET /api/client/v1/usage.

Ids are opaque. A missing id and another customer's id both return 404.

ResourceFields
Conversation id, title (string or null), status, agent (id, name), createdAt. GET one conversation also returns activeRun: { id, status } or null.
Message id, role (user or assistant), content, createdAt, files ({ id, name, mediaType, byteSize }[], empty when there are no files).
Run id, status. A newly accepted message returns status: "queued" and streamUrl.
File id, name, mediaType, byteSize, pageCount, creditsRequired. Belongs to one conversation and one customer. Default max size is 10 MB (PAPERCLIP_ATTACHMENT_MAX_BYTES).

Conversation status is one of idle, running, waiting_approval, blocked, closed, failed.

waiting_approval and blocked are informational. The client cannot approve a gate or clear a block.

Endpoint URL

POST /api/client/v1/conversations/:id/files

Allowed while the app is chatting, including while a run is running and the SSE stream is open. This call does not wake the agent and does not return CONVERSATION_BUSY. A file uploaded during a reply waits on the conversation until the next Send Message cites its id. It does not enter the run already in progress. Default max size is 10 MB (PAPERCLIP_ATTACHMENT_MAX_BYTES).

creditsRequired is a quote for this customer and this file. Uploading does not spend credits and does not increase pagesProcessed. When a run that cited the file finishes successfully, pageCount is added to that customer's pagesProcessed and creditsRequired is subtracted from creditsRemaining. A failed run does not change either number. Counters belong to the customer on the key.

Header

FieldTypeDescription
AuthorizationStringRequired. Bearer pcp_cust_...
Content-TypeStringRequired. multipart/form-data

Body

FieldTypeDescription
fileFileRequired. One part named file.

Response

201

FieldTypeDescription
idStringFile id. Pass it in Send Message fileIds.
nameStringOriginal file name.
mediaTypeStringMedia type, for example application/pdf.
byteSizeIntegerSize in bytes.
pageCountIntegerPages in this file.
creditsRequiredIntegerCredits this customer needs to process this file. A quote, not a charge.

Errors

Stream Run

GET /api/client/v1/runs/9c2e1b70-4a11-4d2e-8f33-1a6b5c7d22e1/stream
Accept: text/event-stream

data: {"type":"status","status":"running"}

data: {"type":"chunk","text":"Invoice 1042 "}

data: {"type":"chunk","text":"is paid."}

data: {"type":"message","id":"c8f20e55-1d66-4a29-8e74-6b1f9d3c8822","role":"assistant","content":"Invoice 1042 is paid.","createdAt":"2026-10-19T06:01:20.000Z","files":[{"id":"e5b02d31-9f88-4c21-a066-8d3f1b7c4455","name":"receipt.pdf","mediaType":"application/pdf","byteSize":12044}]}

data: {"type":"done","status":"idle"}

Endpoint URL

GET /api/client/v1/runs/:runId/stream

One JSON object per data: line. Chunks are published assistant text only. The finished message event includes files. The client can download a listed file immediately and does not wait for done. Upload File and Download File stay open while this stream is open. If the run is already finished, the stream emits message when a reply exists, then done, then closes. waiting_approval is informational. The client cannot approve a gate.

Header

FieldTypeDescription
AuthorizationStringRequired. Bearer pcp_cust_...
AcceptStringRequired. text/event-stream

Query parameters

FieldTypeDescription
None.

Response

SSE. Fields depend on type.

FieldTypeDescription
typeStringstatus, chunk, message, done, or error.
statusStringOn status and done. Conversation status after the event.
textStringOn chunk. Optional on status.
idStringOn message. Assistant message id.
roleStringOn message. assistant.
contentStringOn message. Full assistant reply.
createdAtStringOn message. ISO 8601 time.
filesArrayOn message. Same file objects as List Messages. Empty when there are none.
codeStringOn error. The stream ends. No done follows.
messageStringOn error. Error text.
